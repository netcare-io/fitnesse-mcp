# FitNesse MCP – tools, gates and descriptions (68)

Gates: mode (read/write/test) must be in FITNESSE_TOOLSETS; area complete/debug must be named as well; extra env gates as listed.


## standard

| Tool | Mode | Extra gate | Description |
|---|---|---|---|
| `fitnesse_compare_history` | read | – | Generates a report comparing two test result files for a page history responder call. |
| `fitnesse_compare_versions` | read | – | Shows the differences between two saved versions of a page, or between one version and the latest when only one is given. Version ids as listed by fitnesse_get_versions. Returns HTML. |

| `fitnesse_replace` | write | – | Replaces text in the selected page and all its children and saves every changed page; returns an HTML table of the changed pages. Text replace: search_string is a regular expression. method_replace=true: search_string is a wiki line that evaluates to a method or scenario (e.g. '\|click\|x\|'). search_scope limits it to an ancestor page or 'root'. Try the search with fitnesse_search first: this cannot be undone in one step. |
| `fitnesse_rollback_version` | write | – | Rolls back a page to a selected version identifier from saved versions. |
| `fitnesse_save_account` | write | ALLOW_ACCOUNT_ADMIN | Changes FitNesse accounts (responder=saveAccount), as the account this server logs in with. action='change_password': new password for that account (current_password, new_password). 'create_user' and 'delete_user' need the admin user: user_name, plus user_password for create_user. Only on explicit request. |
| `fitnesse_save_page_content` | write | – | Saves wiki page content via POST using pageContent and optional editTime, ticketId, and redirect fields. FitNesse removes the page's help text and tags when they are not sent, so help_text and suites are kept from the current page unless given; pass an empty string to remove them. Without edit_time the save overwrites the page (last write wins). With edit_time and ticket_id (from fitnesse_get_page_data) FitNesse checks for a conflict: if someone else saved the page since then, nothing is saved and the tool fails; re-read the page, merge, and save again. |
| `fitnesse_save_properties` | write | – | Saves page properties via POST: pageType, attribute flags, Suites tags and HelpText. FitNesse resets every attribute that is not sent, so each argument left out keeps the page's current value; `attributes` is the complete list of flags that end up set. Pass an empty string or list to clear a value. |
| `fitnesse_shutdown` | write | ALLOW_SHUTDOWN | Shuts the FitNesse server down through the shutdown responder. |
| `fitnesse_upload_file` | write | FILES_ROOT | Uploads file content into the files section directory selected by the resource path. Pass text content directly via `content`, or binary/base64-encoded content via `content_base64`. |

## debug

| Tool | Mode | Extra gate | Description |
|---|---|---|---|
| `fitnesse_debug_defined_action_source` | read | – | Reads the current wiki of a defined action for editing: finds the page that defines it via the session's defined actions, reads that page fresh (not what the session loaded) and cuts out the definition block as FitLibrary reads it: the header table (the page's first table or the first after a ----) and every table up to the next ----, with the text in between. Forks with definedAction pick the definition as a run would (keywords, number of arguments, loaded last wins). Result: page, index, last, original, ready for fitnesse_table_save(page_path=page, index=index, last=last, original=original, wiki=<new>, reload_defined_actions=true). On older forks it fails if the header is on the page more than once. Needs a debug session in which the action is loaded, or page_path, the defining page. |
| `fitnesse_debug_inspect` | read | – | Looks into the debug session. kind: - 'keywords': the keywords you can use in tables right now. Without filter: only the categories with their number of keywords (the full list is large). With filter (a word such as 'click', or a category such as 'Web / Browser'; it also searches the help texts): matching entries: syntax, where %1, %2 are the cells for parameters (e.g. 'click %1' -> '\|click\|//button\|'), parameters (label, allowed options), returnType and tableItems (the rows a keyword expects in the rest of its table; mandatory=true marks required rows). details=true adds the help texts. generated=true marks a public method without keyword annotation (category: its class); its syntax works as written. Defined actions are not in it: see 'definedActions'. - 'definedActions': the defined actions loaded in this session by \|define actions at\| (usually from SetUp): action (call syntax, parameters as cells), parameters, note, deprecated, author, page (where it is defined; edit it with fitnesse_debug_defined_action_source) and overrides. filter searches the call, note, author and page, not the action's body: read that with fitnesse_debug_defined_action_source. Empty until the page's 'define actions at' tables have run in the session. - 'dynamicVariables': variables set during the test (name, value); include_system adds the many unchanged Java system properties. - 'scope': the objects whose keywords are available, innermost first (level, name, class, depth). - 'liveView': the open remote browsers (hub, selenium_session, browsers) and live_view_url, a link where a person can watch the selected browser (per browser in 'browsers'; password not included). A 'note' says when the link is on localhost. |
| `fitnesse_debug_page_tables` | read | – | Lists the tables that running a page executes, in order, including those of its SetUp/TearDown and included pages: index, number of rows and the first row. Use the indices to run only some of them with fitnesse_debug_run_page(tables=[...]); setup_tables are those of the SetUp (what run_page(setup_only=true) runs), teardown_tables those of the TearDown (run when the test ends, if they have not run). These indices differ from fitnesse_table_source's, which counts only the page's own tables: to edit a table, use its source_page and source_index with the fitnesse_table_* tools. A table of an included page (included=true, e.g. SetUp) is edited on that page, which changes it for every page that includes it. Requires a debug session; omit page_path for the page currently being tested. |
| `fitnesse_debug_read_link` | read | – | Reads a file a debug result links to, such as the screenshot ('Screen', /files/screenCaptures/...) or the page source at the failure ('HTML', /files/htmlSource/...) that KDTA links from a table. An image comes back as image content. HTML and text: scripts, styles and comments are left out and whitespace is squeezed; with filter only the places that contain it (context_chars around each), to check a locator against the page as it was (an id, a class, a visible text); without filter the beginning (max_chars) and the length. Only links into this FitNesse's files section; needs no session. |
| `fitnesse_debug_status` | read | – | Shows the debug session of this FitNesse account and the new lines of the test process log since the last call. Answers immediately, even while another call is still running a long table, so use it to watch progress. Result: running (false = no session), page (where the session was started), currentPage (whose test is running), suite, busy, idleSecondsLeft (the session ends itself after this idle time), known_to_this_server, and log.lines ('time [out\|err\|info] text', time as this server's local time with its UTC offset, Z = UTC; 'info' lines show the command, exit code and crashes; values of secrets such as Authorization headers, API keys, tokens, cookies and passwords are masked as ***). These describe this server's session, else the account's session on page_path, else its only one. sessions (mod #159) lists all running sessions of the account: session, page, currentPage, suite, busy, startedAt (local time). busy=true means the process is still working on a call that timed out: wait and call this again until busy is false, or abort with fitnesse_debug_end(abort=true). known_to_this_server=false with running=true means someone else's session (or one from before a restart): the other debug tools refuse to touch it, and this server does not take it over: leave it alone; it ends itself after its idle time. |
| `fitnesse_debug_steps` | read | – | Lists the steps noted while building a test: every fitnesse_debug_run_wiki call whose tables all passed (unless run with record=false), in order: step, page (current page then), wiki. 'wiki' joins the kept steps, ready to save as the test's tables with fitnesse_table_insert or fitnesse_table_save_text (read fitnesse_table_source first). drop leaves steps out for good (e.g. tries that don't belong in the test), clear=true forgets all, e.g. after saving. | `fitnesse_table_source` | read | – | Reads a wiki page as its tables and the text between them, for changing single tables with fitnesse_table_save, fitnesse_table_insert and fitnesse_table_delete. Its indices differ from fitnesse_debug_page_tables', which also counts SetUp, TearDown and included pages. Does not need a debug session. |
| `fitnesse_debug_end` | test | – | Ends the debug session as a normal test run ends: first the current page's TearDown tables that have not run yet (e.g. after a stop; teardown.teardown_tables) and, outside a suite session once fitnesse_debug_run_page ran, the SuiteTearDown (suite_teardown); then the test process stops. skip_teardown=true leaves both out. Every end of a page's test (here and in fitnesse_debug_run_page's previous_page_teardown) shows FitLibrary's own table 'Messages in storytest tear down' (here also '... suite tear down'), also when teardown_tables is empty. Returns the tear-down result, the remaining log lines (the last max_log_lines of them; log_omitted counts the others: to read the whole log, call fitnesse_debug_status before ending) and page_totals (counts per page). The log's 'Exit code' is wrong + exceptions of everything the session ran, also before a restart: the pages' results are page_totals. Call it whenever you are done. abort=true stops the process immediately without tear down; it works even while another call is still running. Use it when the session hangs or busy stays true. |
| `fitnesse_debug_run_page` | test | – | Runs the tables of a test page in the debug session, exactly as a normal test run would send them (SetUp, TearDown and included pages included), and stops after the first table with a [fail] or [error] cell, like a debugger: the rest of the page, its TearDown included, has not run, so the browser and state are as the failure left them. The result then has stopped_at (index, source_page, source_index, text_before: the page text just before the table, wiki: the table's wiki to change) and next_table. Like the console in the browser debugger, try corrected versions of the table with fitnesse_debug_run_wiki (runs in the session, saves nothing) until one passes, save that one once (fitnesse_table_save on source_page/source_index). If no version passes (e.g. the application is wrong, not the test), report that instead. Either way, then call this again without tables to continue at next_table. page_done=true: all tables ran. When it stops, the failing table's screenshot (KDTA's 'Screen' link) comes as an image; read its 'HTML' link, the page source then, with fitnesse_debug_read_link(url, filter=...). Result tables as for fitnesse_debug_run_wiki. tables=[...] runs only those indices (see fitnesse_debug_page_tables), in that order, and does not move next_table (repeated in the result while the page's run is stopped). from_table continues the page at that index instead. page_path must be a test or suite page, or one of fitnesse_debug_start's 'pages'. If it is not the page currently being tested, the current page's test is ended first: its TearDown tables that have not run yet (e.g. after a stop) run now, unless skip_teardown=true. previous_page_teardown reports that end (teardown_tables, and tables_not_run if it had stopped). Then the new page's test begins; restart=true ends and begins the current page's test the same way. setup_only=true runs just the SetUp (the tables of the included SetUp page): do this right after fitnesse_debug_start, before fitnesse_debug_run_wiki or inspect. Outside a suite session the first call runs the SuiteSetUp before (result suite_setup), once per session; it stops at a failure as well, and the page's test begins only once it ran to the end. A later call without tables then leaves the SetUp out (skipped_setup lists its indices) instead of running it twice. In a suite session, call it for each page with runnable=true from fitnesse_debug_start's 'pages', in that order, and move on once page_done is true. |
| `fitnesse_debug_run_wiki` | test | – | Runs FitNesse wiki tables in the debug session, e.g. '\|with browser\|'. Rows are '\|cell\|cell\|' lines; separate tables with an empty line. Variables of the current page like ${BASE_URL} are resolved. The page's SetUp and TearDown are NOT added: run the SetUp first with fitnesse_debug_run_page(setup_only=true), otherwise the defined actions, the browser and fixtures it provides are missing. State carries over between calls: a browser opened in one call is still open in the next. All tables of one call run before the result comes back; it can take minutes (up to ~10). Result: 'tables' holds every table as text, one row per line; a cell's outcome is prefixed: [pass] check passed, [fail] check failed (the cell shows '<value> expected ⏎ <value> actual'), [error] exception (message and shortened stack trace), [ignore] not run. Cells without prefix are plain input. Cells of nested tables keep their prefix inline. Under a \|condition\| table a line says what it did (then ran, else ran, condition false, condition error, skipped): only the appended 'Result of then' row shows that then ran. 'counts' are this call's right/wrong/ignores/exceptions; 'page_totals' add up all calls since the current page's test began. Below each table come what belongs to it: folding areas after it ('after: <title>', e.g. FitLibrary's show after or logs), links ('link in row R, column C: text -> url') and images. Inline screenshots ('[image N]' in a cell) are attached as image content (at most 4 per call); 'images' lists which one is where. A [pass] on a click only means the call returned: check its effect (URL, a text, an element's visibility) before the next step. Find the available keywords and their exact wording with fitnesse_debug_inspect(kind='keywords') before writing tables. restart=true first ends the running test (its TearDown tables that have not run yet run, unless skip_teardown=true; result in previous_page_teardown) and begins it afresh: use it for a clean state. |
| `fitnesse_debug_start` | test | – | Starts a debug session for stepwise testing on a KDTA FitNesse: a test process that stays alive between calls, so you can run tables one call at a time and the state (open browsers, objects in scope, variables) carries over from one call to the next. Use it to try out steps, build a new test, or step through a failing one; for a plain complete run use fitnesse_run_test instead. Nothing is written to the test history. The page decides which fixtures and variables are available, so start on the test page or suite page you want to work on; its type decides how (suite=true/false only to override it). Typical flow: fitnesse_debug_start -> fitnesse_debug_run_page(setup_only=true) -> fitnesse_debug_inspect(kind='keywords' or 'definedActions') -> fitnesse_debug_run_wiki or fitnesse_debug_run_page, repeatedly -> fitnesse_debug_end. Run the SetUp first: defined actions, the browser and often fixtures only exist once it has run. One session per page and FitNesse account (forks before mod #159: one per account). If one is already running on this page (possibly a person working in the browser), this fails and says so: then use another page or wait for it to end; this server does not take over sessions it did not start. Sessions on other pages are not affected. This server works with one session at a time: end its own before starting another. Use replace=true only when told to: it kills the running session without tear down, and a browser tab on it then shows 'replaced'. The result says suite (true/false) and lists 'pages' in run order, each with path, kind (test, suiteSetUp, suiteTearDown) and runnable (false = cannot run in this session; skip it). Suite: run each runnable page with fitnesse_debug_run_page, in that order. Test page: the pages around it are its SuiteSetUp and SuiteTearDown (also named as suite_setup/suite_teardown), which run by themselves as in a normal test run: the first fitnesse_debug_run_page runs the SuiteSetUp first, fitnesse_debug_end the SuiteTearDown. Always end the session with fitnesse_debug_end when done: it occupies a server slot and browsers until then. |
